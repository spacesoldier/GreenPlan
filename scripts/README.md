# Служебные скрипты

`archive_foxy_encrypted_home.sh` создаёт файловый `.tar` папки `/home/foxy` на внешнем диске. Скрипту передаётся полный целевой каталог; исходник не удаляется.

```bash
sudo ./scripts/archive_foxy_encrypted_home.sh /media/sol/Expansion/jobs/contracts/2026/foxy
```

Скрипт требует реальную mount point, отказывается писать на `/home` или FAT32 и проверяет свободное место с запасом 1 GiB. В результате получаются `.tar` и `.tar.sha256`.

Важно: это **не** поблочный архив шифртекста. Он годится только когда каждый файл доступен через смонтированную файловую систему. Сообщение `tar: ... Cannot open: Required key not available` означает, что ключ файлового шифрования для этого объекта отсутствует; такой запуск завершается с ошибкой, а созданный `.tar` неполный. Не удаляйте исходник и не считайте этот файл резервной копией.

Для сохранения недоступных без ключа данных нужен образ содержащей их ext4-файловой системы (например, `e2image` с данными) либо сначала надо восстановить/подключить ключи `fscrypt`. Образ `/dev/nvme0n1p4` будет включать не только `foxy`, а весь раздел `/home`; перед его созданием нужно отдельно согласовать объём и состав сохраняемых данных.

## Полный архив домашнего каталога

`archive_user_home.sh` делает файловый бэкап одного локального пользователя: только фактические файлы, без неиспользуемого пространства ext4-раздела. Он сохраняет ACL, extended attributes, числовые UID/GID и sparse-файлы. По умолчанию пользователь — `sol`.

```bash
sudo ./scripts/archive_user_home.sh /media/sol/Expansion/hp_laptop_backup/autumn2026
```

Результат — `sol-home-<timestamp>.tar` и рядом проверочная сумма `.sha256`. Временные Unix-сокеты игнорируются: это запущенные IPC-каналы, а не восстанавливаемые данные. Скрипт не удаляет исходные файлы.
