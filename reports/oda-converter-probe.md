# ODA File Converter: пробная конвертация двух пилотов

Дата прогона: 2026-09-22.

## Среда и лицензирование

- официальный Linux DEB ODA File Converter `27.1.0.0` был скачан во временный каталог `/tmp` и распакован без установки в ОС;
- бинарник и полученные DXF не добавлялись в репозиторий;
- на Linux бинарник требует X11/Qt даже в CLI-режиме, поэтому для headless-прогона использовался `xvfb-run -a`;
- согласно FAQ ODA, не-члены могут применять File Converter для некоммерческих задач. Это покрывает исследовательский хакатонный probe как рабочее допущение, но не является разрешением на распространение бинарника внутри будущего Docker-образа.

## Команда

Временная staging-папка содержала ровно по одной **копии** каждого DWG. Исходные файлы датасета не менялись.

```bash
xvfb-run -a --server-args='-screen 0 1280x1024x24' \
  ODAFileConverter INPUT_DIR OUTPUT_DIR ACAD2018 DXF 0 1 '*.dwg'
```

Аргументы означают: выходной DXF R2018 (`AC1032`), без рекурсивного обхода, с включённым audit и фильтром только `*.dwg`.

## Что означают proxy-objects Песчаного

`ACAD_PROXY_OBJECT` — неграфический объект базы чертежа, который записан, но не интерпретируется текущим набором Object Enabler/библиотек. Это не то же самое, что `ACAD_PROXY_ENTITY`: proxy-entity могла бы содержать нераспознанную видимую геометрию. В Песчаном proxy-entities не найдено.

В DXF Песчаного присутствуют обычные графические записи: `LINE`, `LWPOLYLINE`, `CIRCLE`, `ARC`, `SPLINE`, `HATCH`, `INSERT`, `MTEXT`, `IMAGE`, а также blocks и layers. Среди объявленных классов видны механизмы динамических блоков, associative arrays, XREF/терминальных настроек, таблиц и AEC-tracker. По одному proxy-object нельзя безопасно утверждать его бизнес-смысл, поэтому их нельзя использовать как основу ограничений до отдельной классификации.

Практический вывод: **оба пилота можно подавать на DXF-пайплайн; Песчаный получает статус `accepted_with_review` до визуального diff и проверки XREF.** Отсутствие сообщений в логе конвертера не доказывает отсутствие потерь; оно доказывает лишь, что ODA не сообщил об ошибке audit/чтения/записи.

## Как заглядывать в DWG без AutoCAD

1. **ODA File Converter → DXF R2018 → собственный инспектор/`ezdxf`.** Рекомендуемый путь для MVP. После конверсии можно детерминированно посчитать layers, blocks, entity types, proxy records, extents, XREF и извлечь геометрию. Сам ODA сообщает ошибки чтения/audit/записи, но не заменяет содержательный per-object отчёт.
2. **ODA Drawings SDK.** Профессиональный путь для прямого доступа к базе DWG и объектам; требует подходящей лицензии, а для отраслевых AEC/Civil/Map-объектов — соответствующих расширений. Не нужен для первого MVP.
3. **LibreDWG.** Свободный CLI/библиотека для первичной диагностики и части старых DWG; не принимается как единственный production-reader для R2018/DWG с нестандартными объектами.
4. **QCAD Professional / другие коммерческие CAD с DWG-модулем.** Полезны для просмотра и ручной диагностики, но не дают нам автоматически проверяемого, переносимого backend-контракта.
5. **Облачные Autodesk-сервисы.** Возможны как внешняя интеграция, но добавляют сетевую, лицензионную и контурную зависимость; не подходят как единственный путь для целевой МосТех.ОС.

## Следующий технический шаг

Сделать внутренний `cad-inventory` для созданных DXF, который строит JSON до/после: версии, extents, layers, blocks, entity types, proxy entities/objects, XREF, текстовые стили и список файловых зависимостей. Конвертер должен считаться успешным только при наличии DXF **и** прохождении этого inventory + визуального diff выбранных листов.
