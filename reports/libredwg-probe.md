# LibreDWG: диагностический прогон на пилотном DWG

Дата прогона: 2026-09-22.

## Назначение

LibreDWG применяется здесь как независимый read-only диагностический reader, а не как основной конвертер. Образ `greenplan/libredwg:0.13.3` собран из GNU LibreDWG 0.13.3 с проверкой SHA-256 исходного архива; лицензия — GPL-3.0-or-later. Он не включается в закрытый backend без отдельной лицензионной оценки.

## Вход и команда

Временная папка содержала одну копию того же файла, что и успешный ODA-пилот:

`dataset/Пилотный проект 20 улиц/14. Куликовская улица/Проектные решения/DWG/Генеральный план.dwg`

```bash
docker run --rm \
  -v /tmp/oda-docker-input:/data:ro \
  -v /tmp/libredwg-output:/out \
  greenplan/libredwg:0.13.3 \
  -v1 -O JSON -o /out/pilot.json /data/pilot.dwg
```

## Результат

| Проверка | Значение |
|---|---|
| Сигнатура исходника | `AC1032` / DWG R2018 |
| Код процесса | `0` |
| JSON | 162 724 696 байт |
| stderr | 888 байт, 19 строк предупреждений/ошибок декодера |
| ODA на том же исходнике | DXF `AC1032`, 57 612 163 байта, код `0` |

LibreDWG прочитал файл и выпустил JSON, но сообщил CRC mismatch, нестабильные классы `MATERIAL`, `TABLESTYLE`, `MLEADERSTYLE`, противоречивый `num_inserts`, ошибки чтения буфера и отсутствие `Template` section. Это **не доказательство порчи DWG**: ODA прочитал и преобразовал этот же файл без ошибки. Это доказательство того, что LibreDWG не следует использовать как единственный источник истины или как экспортёр DXF для современных планов.

## Решение

- Использовать LibreDWG для второго мнения: определить версию, попытаться извлечь JSON/GeoJSON, сохранить warnings как сигнал `needs_review`.
- Основной путь DWG→DXF для MVP — ODA adapter с audit и последующим inventory/visual diff.
- Если ODA и LibreDWG расходятся, исходный DWG не исправлять автоматически: сохранять оба лога и передавать файл на проверку.
- Не запускать `dwgread -v5` в batch: максимальная детализация produces сотни мегабайт trace на одном 8.9-МБ DWG. Для batch подходит `-v1`.
