# Выдача DXF без изменения исходного проекта

## Принцип

`dataset` — первичный архив входящих материалов. DWG, PDF, XREF и другие исходные файлы в нём никогда не переименовываются, не перемещаются и не заменяются конвертацией. Производный DXF создаётся только из зарегистрированного успешного ODA-артефакта, чья связь с исходником и SHA-256 есть в PostgreSQL.

Для каждой улицы используются два представления одного производного DXF:

1. **Локальное рядом с проектом**: `<папка улицы>/dxf/<путь исходника внутри улицы>.dxf`.
2. **Переносимое**: `platform/exports/dxf-only/<папка улицы>/<путь исходника внутри улицы>.dxf`.

Путь после папки улицы и все промежуточные каталоги сохраняются. Меняется только корень выдачи и расширение `.dwg` на `.dxf`. Так DXF не смешивается с исходным DWG в его рабочей папке, но его происхождение остаётся очевидным.

Пример:

```text
Исходник:
14. Куликовская улица/Проектные решения/DWG/Генеральный план.dwg

Рядом с проектом:
14. Куликовская улица/dxf/Проектные решения/DWG/Генеральный план.dxf

Для передачи:
exports/dxf-only/14. Куликовская улица/Проектные решения/DWG/Генеральный план.dxf
```

В переносимом дереве разрешены только `.dxf`; JSON LibreDWG, логи, исходные DWG и служебные манифесты туда не попадают. Техническая диагностика остаётся в `platform/work/jobs` и PostgreSQL.

## Защитные правила

- сначала создаётся временный файл рядом с целью, проверяется SHA-256, затем выполняется атомарная замена;
- существующий DXF с тем же хешем не копируется заново (`already_present`);
- существующий DXF с другим хешем не перезаписывается без явного `--overwrite`;
- массовая выкладка выбирает один завершённый job на уникальный SHA-256 исходного DWG, поэтому дубли задач не дают дубли DXF;
- публикацию делает только `control`-контейнер от UID/GID пользователя рабочей папки; Celery-worker’ы продолжают монтировать `dataset` только для чтения.

## Команды

```bash
cd platform
docker compose --env-file .env --profile tools run --rm control publish <job UUID>
docker compose --env-file .env --profile tools run --rm control publish-completed --dry-run
docker compose --env-file .env --profile tools run --rm control publish-completed
```

Массовая выкладка всех 20 проектов допускается только после успешного конвертационного прогона и просмотра `--dry-run`.
