# Геометрический и посадочный движок

## Конвейер расчёта

```text
нормализованная сцена + почва/рельеф
  → классифицированные нормативные ограничения
  → буферы по типу посадки
  → union запретов
  → зона работ минус запреты
  → кандидаты на сетке / вдоль оси / внутри полигонов
  → проверка кроны, открытой земли и корнеобитаемого объёма
  → при допустимости: варианты подготовки места и проектного грунта
  → отбор с целевой функцией
  → геометрическая, биологическая и нормативная валидация
```

Расчёт выполняется раздельно для профилей посадок. Один и тот же объект может быть допустим для кустарника и запрещён для дерева.

## Профиль посадки

```yaml
profile_id: tree.standard
kind: tree
crown_diameter_m: 5.0
min_distance_same_kind_m: 5.0
candidate_strategy: grid_and_linear
required_rules:
  - utility.clearance
  - building.clearance
  - road.clearance
  - existing_tree.clearance
```

Числа выше — пример формата, не утверждённая норма. Реальные значения подставляются только из проверенного rulebook.

Профиль также ссылается на стадии роста и положительные требования: проекцию кроны, площадь открытой земли, эффективную глубину, корнеобитаемый объём, свойства грунта, дренаж и воду. Эти требования поступают из проверенного биологического/технического справочника, а не смешиваются с юридическим rulebook.

## Ограничения

Каждое ограничение имеет форму `геометрия + применимое правило + буфер + достоверность`. Запретная область рассчитывается геометрическим буфером с консервативной точностью. Неизвестный тип сети не должен интерпретироваться как отсутствие сети: его политика задаётся конфигом (`block`, `review`, `ignore`), по умолчанию — `block`.

Допустимая область для профиля `p`:

```text
allowed(p) = site_boundary ∩ planting_area − union(buffer(constraint_i, rule_i(p)))
```

`allowed(p)` отвечает только на разрешительно-пространственную часть. Итоговая пригодность точки дополнительно требует:

```text
feasible(p, x) = allowed(p, x)
              AND crown_space(x) satisfies crown_requirement(p)
              AND rootable_soil(x) satisfies root_requirements(p)
              AND preparation_package(x) is constructible
```

Если существующего грунта недостаточно, движок может рассматривать выемку, отсыпку, замену/разуплотнение грунта, дренаж, полив или конструктивный почвенный объём. Каждое действие формирует новую проектную версию состояния и само проходит проверки относительно коммуникаций, отметок и водоотвода.

Перед вычитанием геометрия очищается от самопересечений и фиксируется заданная допусковая точность. Все операции выполняются в метрах.

## Кандидаты и целевая функция

Достаточно начать с объяснимых стратегий:

- регулярная сетка в полигоне;
- равномерное размещение вдоль оси улицы/аллеи;
- выбор из пользовательских зон посадки;
- сохранение минимальной дистанции до существующих и предложенных растений.

Затем детерминированно отбирать кандидаты по взвешенной функции:

```text
score = w_coverage * озеленяемая_площадь
      + w_context  * соответствие_типу_зоны
      - w_edge     * близость_к_границе_допустимости
      - w_density  * нарушение_желаемой_плотности
      - w_review   * неопределённость_исходных_данных
```

Весам, seed и версии стратегии присваивается идентификатор в манифесте запуска. Случайные генераторы без фиксированного seed не допускаются.

## Валидации

Для каждой принятой точки проверяются:

1. принадлежность зоне работ и допустимой зоне;
2. расстояние до каждого релевантного ограничения;
3. расстояние до существующих/предложенных растений;
4. отсутствие дубликата и самопересечения экспортируемой геометрии;
5. наличие правила, версии и источника объяснения;
6. отсутствие зависимости от объекта с `needs_review`, если политика не разрешает это явно.
7. достаточность надземного пространства для расчётной кроны;
8. достаточность площади, глубины и объёма корнеобитаемого грунта;
9. выполнимость и безопасность всех подготовительных действий.

Провал проверки не исправляется «сдвигом на глаз»: точка отклоняется или заново выбирается, а причина сохраняется.
