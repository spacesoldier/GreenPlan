# ADR-0038 — Сгруппированные CAD-классы и автоподтверждение по каноническому имени

- Status: Accepted
- Date: 2026-09-29
- Owners: CAD domain, backend, frontend, ML
- Related phase: Phase 4, iteration 2
- Supersedes in part: ADR-0020 human-only review gate, ADR-0037 запрет нового `utility.unknown`
- Superseded by: —

## Context

Конечные классы ADR-0037 нужны для применения правил СП 42, однако плоский список из десятков
классов замедляет ручной разбор. В XREF встречаются слои с именами `Водопровод`, `Газопровод`,
`Кабель связи`, `Бортовой камень` и другими названиями, буквально совпадающими с закрытой taxonomy.
Требовать для них отдельного принятия машинной подсказки не добавляет инженерного знания.

## Decision

Интерфейс группирует конечные классы по навигационным доменам: растительность, здания и
сооружения, улицы и дорожки, инженерные сети, границы и зоны, рельеф. Группа не заменяет
`object_class`: в БД сохраняется конечный код.

`utility.unknown` разрешён как честный временный класс для слоя инженерной сети неизвестного типа.
Он не активирует нормативные ограничения конкретного вида сети и требует уточнения до расчёта,
которому нужен точный тип.

Перед вызовом LLM file-scoped semantic worker выполняет детерминированное сопоставление имени слоя:

- нормализует регистр, `ё/е`, разделители и цифровые номера;
- удаляет только известные служебные начальные слова вроде `слой`, `существующий`, `проектируемый`;
- подтверждает буквальное совпадение, единственное близкое совпадение с порогом 0.94 или включение
  канонического названия с не более чем двумя дополнительными словами;
- при конкуренции двух классов ничего автоматически не назначает;
- LLM получает только оставшиеся случаи.

Автоматическое решение получает `review_status=accepted` для удобства prototype workflow, но не
выдаётся за действие инженера: `axis_results.auto_confirmed=true`, resolution method,
`provider_run.model_invoked=false`, classification review и audit event сохраняют происхождение.
Интерфейс пишет «подтверждено по названию слоя». Инженер может позднее изменить класс обычным
массовым review.

## Alternatives considered

### Оставить плоский список и ручное принятие каждого слоя

Сохраняет единый gate, но создаёт лишнюю работу для буквальных совпадений и плохо масштабируется.

### Автоматически принимать любое решение LLM высокой уверенности

Не принято: вероятность модели не доказывает нормативный класс, особенно для сокращений и
подрядческих кодов. Автоподтверждение ограничено проверяемым лексическим правилом.

### Назначать только широкие домены

Не принято: домена недостаточно для выбора расстояний СП 42. Широкий `utility.unknown` допускается
только как явно неполный результат.

## Consequences

### Positive

- буквальные и почти буквальные слои больше не требуют двух действий;
- конечная нормативная taxonomy сохраняется;
- длинный список становится обозримым за счёт смысловых групп;
- вызов CPU-модели не тратится на очевидные слои;
- автоматические и человеческие решения различимы по provenance.

### Negative / trade-offs

- порог и список служебных слов становятся версионируемым правилом;
- `accepted` пока объединяет два происхождения, различаемые через metadata;
- укрупнённый `utility.unknown` нельзя использовать как точный источник нормативного буфера.

## Verification

- точные `Кабель связи` и `Водопровод` подтверждаются без вызова модели;
- `Проектируемый водопровод` и безопасная близкая опечатка дают тот же класс;
- неоднозначный `Кабель связи силовой` и произвольный `A-42-X` остаются на review;
- UI показывает optgroup по крупным доменам и быстрый `utility.unknown`;
- автоматический слой помечен как подтверждённый по имени, а не проверенный инженером;
- API, web tests/typecheck и production builds проходят.
