# ADR-0020 — Rule-first классификация файлов и CAD-слоёв с модельными подсказками

- Status: Accepted
- Date: 2026-09-27

## Контекст

Папка подрядчика смешивает исходные данные, проектное решение, архивные версии, ведомости,
PDF-листы и XREF. Имена слоёв также не стандартизованы: встречаются русские сокращения,
коды подрядчика и почти бессодержательные имена. Полностью ручная сортировка плохо
масштабируется, но ответ небольшой модели нельзя считать установленным фактом.

## Решение

Вводится единый механизм `classification_suggestion` для file, CAD layer и позднее block/text:

1. Сначала выполняются детерминированные правила по пути, типу, структуре CAD и статистике
   сущностей. Они быстры, объяснимы и дают устойчивые ответы для известных соглашений.
2. Неуверенные случаи могут передаваться decision model. На вход идут только метаданные и
   малые безопасные выборки: путь, имя слоя, типы/число сущностей, имена блоков и тексты.
3. Модель возвращает категорию из закрытого словаря, вероятности и альтернативы; она не
   перемещает файлы, не удаляет архив и не утверждает semantic class.
4. Инженер подтверждает или отклоняет подсказку. Только подтверждённое решение влияет на
   каноническую модель; история решений становится датасетом для последующей донастройки.
5. Низкая уверенность, конфликт rule/model и новые категории всегда получают
   `needs_review`.

### Выбор компонентов

- `ax-llm/ax` — полезный TypeScript-first DSPy-подобный orchestration framework, но не
  обязателен для первого Python pipeline. Его можно подключить позднее на уровне BFF/agent
  orchestration.
- `google/ax` — другой проект: Kubernetes runtime для массовых agent workloads; для локальной
  классификации поставки не применяется.
- Laya — основной кандидат на локальный typed decision provider: закрытые choice/score
  ответы, вероятности, мультиязычная модель. Подключается за provider interface после
  отдельной проверки на русских слоях.
- Jev не фиксируется как обязательная зависимость: название относится к нескольким разным
  продуктам/моделям. Совместимый provider допустим после идентификации конкретной модели,
  лицензии и измерения качества.

Конкретный Jev AI и стратегия его сравнения с Laya позднее выделены в
[ADR-0023](0023-typed-decision-provider-jev-and-laya.md); до принятия нового ADR текущий
rule-first и human-review контракт остаётся без изменений.

## Категории поставки v1

`project_solution`, `source_data`, `survey_existing`, `xref_dependency`, `register`,
`normative`, `archive`, `service_noise`, `unknown`.

Категории CAD v1 используют `geo.object_classes`: сети, здания, дороги/дорожки, покрытия,
границы/охранные зоны и существующая/проектная растительность.

## Verification

- правила объясняют каждый score набором cues;
- одинаковый input snapshot и classifier version дают одинаковый результат;
- suggestion не меняет канонический class без review decision;
- UI показывает вероятность, метод, альтернативы и состояние проверки;
- оценочный набор из реальных 20 проектов измеряет accuracy по каждой категории, а не только
  общую accuracy.
