# ADR-0048: Накопительные редакции семантики поверх неизменяемой геометрии

- Status: Accepted
- Date: 2026-09-30
- Owners: domain / API / web
- Related phase: Phase 4, iteration 3
- Supersedes: —
- Superseded by: —

## Context

В spatial viewer инженер видит геометрию и может точнее классифицировать CAD-слой. Сейчас review записывается в intake, а интерфейс предлагает заново опубликовать всю каноническую модель. Для серии небольших исправлений это дорого, медленно и создаёт ложное впечатление, что геометрия изменилась.

Нужна рабочая редакция, в которой много переназначений классов накапливаются как diff, а пользователь явно сохраняет их одной новой версией. Исходная опубликованная геометрия должна оставаться неизменяемой и воспроизводимой.

## Decision

Вводим `model semantic revision`, привязанную к базовой `canonical_model`:

- черновик содержит набор операций `reclassify_layer`, а позднее `reclassify_object` и `override_property`;
- ключ операции включает стабильную идентичность источника: asset, layer identity и при необходимости object stable key;
- повторная правка того же ключа заменяет значение внутри черновика, но сохраняется в audit log;
- viewer применяет базовую геометрию и активный semantic diff при чтении, не копируя геометрию;
- кнопка `Сохранить версию` атомарно фиксирует весь черновик, присваивает номер и content fingerprint;
- после сохранения создаётся новый пустой черновик; предыдущая версия остаётся доступной по deep link;
- публикация полной новой canonical model нужна только при изменении состава корней, XREF, координат или геометрии.

Версия хранит автора, время, комментарий, base model id, parent semantic revision id и список операций. Материализованное отображение class code разрешено как rebuildable projection для быстрых пространственных запросов.

## API and UX contract

- `GET /v1/models/{model_id}/semantic-revisions/current` возвращает базовую и текущую сохранённую версии, черновой diff и fingerprint.
- `PATCH /v1/models/{model_id}/semantic-draft/layers/{layer_identity}` добавляет или заменяет одну операцию.
- `POST /v1/models/{model_id}/semantic-revisions` фиксирует накопленный diff с optimistic lock по base fingerprint.
- В viewer появляется счётчик несохранённых правок и кнопка `Сохранить версию`; одиночный select больше не утверждает, что нужна полная перепубликация.
- До сохранения правки восстанавливаются после перезагрузки с сервера, а не только из local state.

## Consequences

Плюс: десятки семантических исправлений сохраняются одной дешёвой версией, геометрия не дублируется. Минус: чтение модели становится композицией base + diff; экспорт в DXF обязан фиксировать точную semantic revision.

## Verification

- десять переназначений создают один draft из десяти эффективных операций;
- повторная правка одного слоя не создаёт две конфликтующие эффективные операции;
- сохранение не копирует строки `geo.object_geometries`;
- URL с semantic revision воспроизводит прежнюю классификацию;
- конфликт двух редакторов возвращает `409`, не теряя ни один draft;
- geometry/XREF change по-прежнему требует новой canonical model.
