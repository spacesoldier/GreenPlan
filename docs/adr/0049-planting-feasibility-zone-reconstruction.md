# ADR-0049: Восстановление кандидатных зон озеленения и нормативное вычитание ограничений

- Status: Accepted
- Date: 2026-09-30
- Owners: domain / geospatial / CAD / web
- Related phase: Phase 4, iteration 3
- Supersedes: —
- Superseded by: —

## Context

CAD-поставки редко содержат готовый надёжный полигон `можно сажать`. В Старом Гае слой `Леса и газоны` в основном содержит точки, окружности, дуги и линии условных обозначений, расположенные примерно в центрах интересующих областей. При этом обнаружены отдельные замкнутые полигоны слоя `ДВ_ГП_П_Газон`. HATCH может потеряться при DWG→DXF либо сохраниться как разметочная сетка без явной границы.

Уже имеются классифицированные здания, дороги, сети, рельеф, границы работ и правила СП 42 с разными отступами для деревьев и кустарников. Поэтому зоны следует вычислять, сохраняя отличие между исходной площадью, реконструированной гипотезой и нормативно допустимым остатком.

## Decision

Viewer имеет взаимоисключающие инструменты. `Навигация` использует ЛКМ для pan, колесо для zoom, Shift или ПКМ для rotate и обычный click для выбора объекта. `Обозначить газон` превращает одиночный click в seed point для поиска области; drag в этом режиме не создаёт seed. Активный режим видим в toolbar, отражён курсором и восстанавливается безопасно как `Навигация` после перезагрузки. Кнопка общего `Запустить анализ` из spatial viewer удаляется: анализ запускается предметным инструментом.

Контракт поиска области: `POST /v1/models/{model_id}/surface-regions:detect` получает publication root, semantic revision и CAD point. Сервер использует только surface-forming classes (`transport.*`, `surface.*`, footprints `structure.*`, `territory.work_boundary` и явно разрешённый terrain linework), исключает `utility.*` и подземные коммуникации из polygonize. Ответ возвращает draft polygon, confidence, edge/source ids и диагностические причины. Подтверждение пользователя создаёт версионируемую lawn annotation; оно не переписывает исходную CAD-геометрию.

Расчёт выполняется детерминированным PostGIS-конвейером отдельно для `planting.tree`, `planting.shrub` и `planting.grass`.

### 1. Candidate domain

Источники кандидатов по убыванию доверия:

1. явный замкнутый полигон слоя газона/озеленения;
2. корректная граница работ с вычитанием известных покрытий и зданий;
3. полигон, восстановленный из linework (`ST_Node` → `ST_Polygonize`), содержащий seed-маркер `Леса и газоны`;
4. участок без замкнутого контура не становится effective zone и получает `needs_review`.

Seed-маркер подтверждает назначение, но сам не задаёт площадь. Разметочная сетка/HATCH используется только как evidence для ранжирования и проверки покрытия.

### 2. Constraint zones

Для каждого утверждённого правила и подходящего класса объектов строится зона ограничения оператором правила (`ST_Buffer`, footprint/inside/no-overlap). Размеры считаются только в подтверждённой метрической системе координат. Неизвестная CRS блокирует effective-расчёт.

### 3. Feasible zones

Для каждой intervention class:

`feasible = candidate_domain - union(effective prohibitions and minimum-clearance buffers)`.

Результат нормализуется `ST_MakeValid`, извлекаются polygonal components, отбрасываются фрагменты меньше настраиваемой минимальной площади/ширины. `require_review` не вычитается молча: он создаёт отдельный overlay и снижает readiness.

### 4. Provenance

Каждая зона хранит base model, semantic revision, rule set, intervention class, исходные polygon/seed ids, участвовавшие constraint zone ids, processing run и метрики площади до/после. UI показывает причину каждого выреза и позволяет включать слои `кандидат`, `запрет`, `требует проверки`, `доступно`.

## Alternatives considered

- Считать круг вокруг условного обозначения зоной — отклонено: символ не задаёт границу.
- Использовать только зелёный цвет/HATCH — отклонено: цвет и hatch нестабильны при конвертации.
- Вычитать все unknown-объекты — отклонено: получится ложно пустая территория; unknown блокирует readiness или показывается как review overlay.

## Verification

- fixture с замкнутым газоном и seed выбирает явный полигон, не круг маркера;
- linework с небольшим gap не замыкается автоматически сверх заданного tolerance;
- для одной сети зоны дерева и кустарника различаются согласно rule distance;
- каждый фрагмент результата трассируется до правила и исходного объекта;
- расчёт при неметрической/неизвестной CRS не выдаёт effective result;
- повторный запуск с тем же fingerprint идемпотентен;
- Старый Гай показывает отдельно найденные `ДВ_ГП_П_Газон` и гипотезы вокруг markers `Леса и газоны`.
