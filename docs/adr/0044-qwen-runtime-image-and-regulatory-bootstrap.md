# ADR-0044: Образ Qwen и идемпотентная загрузка нормативной базы

- Status: Accepted
- Date: 2026-09-29
- Owners: platform / knowledge pipeline
- Related phase: Phase 4, iteration 2
- Supersedes: —
- Superseded by: —

## Context

GreenPlan должен запускаться воспроизводимо на новой машине и после первого старта содержать не только файл СП 42.13330.2016, но и пригодный к поиску корпус фрагментов и очередь формализованных нормативных кандидатов. Сейчас PDF уже входит в поставку, а миграция `016` содержит вручную подготовленное ядро правил. Однако наличие PDF и нескольких seed-записей не является разбором документа: текст, его положение на страницах, версия модели, prompt и происхождение каждого кандидата должны быть воспроизводимы.

Локальный runtime сейчас знает Qwen, Gemma и YandexGPT и ожидает общий каталог моделей. Это удобно в разработке, но непригодно как публичный образ: Qwen3-4B распространяется по Apache-2.0, тогда как Gemma и YandexGPT имеют отдельные условия. Кроме того, загрузка модели при каждом старте не должна повторно скачивать гигабайты или блокировать запуск API.

## Decision

Публичной воспроизводимой конфигурацией становится один CPU runtime с Qwen3-4B Q4_K_M. Он публикуется в репозитории образов `spacesoldier/greenplan-llm-runtime` под неизменяемым тегом, содержащим модель, квантование и короткий digest, и дополнительно может получать release-тег приложения.

Образ:

- наследуется от закреплённой версии `llama.cpp`;
- содержит ровно один разрешённый публичный профиль `cad-qwen`;
- кладёт GGUF, лицензию/README источника и `SHA256SUMS` в отдельный ранний слой, чтобы изменения supervisor не дублировали веса;
- проверяет SHA-256 модели во время сборки;
- записывает OCI labels с моделью, исходным URL, лицензией, git revision и digest;
- не содержит Gemma, YandexGPT, пользовательские данные или результаты анализа.

Список активных профилей задаётся `LLM_ENABLED_PROFILES`. Health-check требует только включённые профили. Отсутствие выключенной Gemma или YandexGPT не переводит Qwen-only runtime в `unhealthy`. Compose запускает один runtime; Docker content store не хранит одинаковый слой весов по копии на каждый контейнер.

Разбор СП выполняет отдельная одноразовая команда/служба `regulatory-bootstrap`, а не API startup hook. Конвейер имеет два рубежа:

1. Детерминированно зарегистрировать документ и редакцию, извлечь page-aware текст, нормализовать его и записать сегменты с точными page/locator и source fragment.
2. Возобновляемой фоновой задачей передать сегменты Qwen, получить типизированные `rule_candidates`, проверить JSON Schema и предметные ограничения, после чего показать кандидатов человеку.

Ключ идемпотентности состоит из SHA-256 PDF, версий extractor и segmenter, версии prompt/schema и digest образа модели. Повторный запуск с тем же ключом не создаёт дубликаты. Сбой продолжает незавершённые сегменты. Изменение любого компонента создаёт новый ingestion run и сохраняет предыдущий для аудита.

Qwen никогда не создаёт исполняемое правило напрямую. Его вывод остаётся в `rules.rule_candidates`; только подтверждённый человеком кандидат может породить запись `rules.rules` и войти в утверждённый `rule_set`. Ранее вручную подготовленные правила миграции `016` не дублируются и не перезаписываются: bootstrap связывает с ними подтверждающие фрагменты либо создаёт отдельные кандидаты на сверку.

## Alternatives considered

### Монтировать все модели с хоста

Сохраняется как developer override, но не является воспроизводимой публичной поставкой и требует ручного скачивания.

### Запечь Qwen, Gemma и YandexGPT в один образ

Отклонено: образ становится избыточно тяжёлым, а лицензии Gemma и YandexGPT требуют отдельной оценки. Для первой поставки достаточно Apache-2.0 Qwen.

### Разбирать СП при каждом старте API

Отклонено: долгий и недетерминированный inference ухудшает availability, может создавать дубликаты и смешивает жизненный цикл приложения с импортом знаний.

### Автоматически публиковать извлечённые правила

Отклонено: ошибка модели в нормативном ограничении может сделать результат проектирования небезопасным.

## Consequences

### Positive

- новая установка получает известную модель и воспроизводимый нормативный bootstrap;
- дорогой inference кэшируется по полному fingerprint и продолжается после сбоя;
- происхождение каждого кандидата прослеживается до страницы PDF и версии модели;
- публичный образ имеет понятную лицензионную границу.

### Negative / trade-offs

- Qwen-образ будет весить несколько гигабайт и потребует отдельного времени публикации;
- изменение prompt или модели создаёт новый run, а не мутирует старый;
- для превращения кандидатов в действующие правила остаётся обязательный human review;
- Gemma и YandexGPT в публичную поставку пока не входят.

## Verification

- сборка падает при несовпадении SHA-256 GGUF;
- Qwen-only контейнер становится healthy без файлов Gemma/YandexGPT;
- два запуска bootstrap с одним fingerprint оставляют по одному document edition, segment set и candidate set;
- оборванный запуск продолжается без повторной обработки завершённых сегментов;
- каждый кандидат имеет model digest, prompt hash и locator исходного фрагмента;
- ни один непроверенный кандидат не входит в active rule set;
- установка на пустой PostGIS показывает документ и прогресс разбора в разделе «Библиотека».
