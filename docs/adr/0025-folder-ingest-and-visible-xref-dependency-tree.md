# ADR-0025 — Загрузка каталога и видимое дерево XREF-зависимостей

- Status: Accepted
- Date: 2026-09-27
- Owners: frontend, backend, CAD ingestion
- Related phase: Phase 3, iteration 2
- Supersedes: —
- Superseded by: —

## Context

Кнопка «Загрузить папку проекта» фактически открывала обычный multi-file picker: атрибут
`webkitdirectory` добавлялся после render через effect и оказался ненадёжным. Выбранные
пользователем DWG попадали в корень delivery, `webkitRelativePath` отсутствовал, а ссылки вида
`..\00_Ссылки\03_Подгрузки\base.dwg` не могли разрешиться.

Backend уже извлекал XREF, искал их сначала по delivery-relative path, затем по basename и
сохранял статусы `resolved`, `missing` и `ambiguous`. Но UI показывал только суммарные findings.
Пользователь не видел область поиска, направление связей и общие зависимости нескольких
головных DWG.

## Decision

Directory picker получает атрибуты непосредственно при render. Folder-upload принимается
только если браузер вернул непустой `webkitRelativePath` для каждого файла и один общий root.
Иначе загрузка останавливается с объяснением; тихое превращение папки в набор корневых файлов
запрещено. Отдельный multi-file upload остаётся отдельным явно обозначенным режимом.

XREF resolver ограничен текущей immutable delivery. Он не обходит серверный dataset, другие
проекты или произвольную файловую систему: такой глобальный bind был бы невоспроизводим и мог
бы подключить одноимённый файл другого подрядчика. При повторном анализе добавленные файлы
участвуют в разрешении зависимостей.

Project detail API публикует XREF edges вместе с source/target delivery paths, исходным путём,
статусом, кандидатами, attach/overlay и числом placements. Intake UI строит документ-ориентированное
дерево. Неразрешённые цели остаются полноценными видимыми узлами; одинаковая зависимость
показывает число ссылающихся DWG.

## Consequences

- загрузка каталога сохраняет структуру, необходимую для точного relative-path resolution;
- одиночные файлы допустимы, но UI предупреждает, что соседние XREF сами не загрузятся;
- пользователь видит, почему ссылка не найдена и где DWG ожидал файл;
- отсутствие зависимости нельзя спутать со сбоем ODA или классификатора;
- folder picker зависит от browser Directory Upload API; для неподдерживающего браузера UI
  предлагает Chromium-family browser либо осознанную загрузку отдельных файлов;
- force-directed граф можно добавить позднее, но дерево остаётся основным диагностическим
  представлением: оно лучше передаёт пути и статусы больших поставок.

## Verification

- folder selection без `webkitRelativePath` отклоняется до первого HTTP upload;
- вложенный файл сохраняется как `<root>/<folders>/<name>`, а не только basename;
- UI явно сообщает scope поиска;
- каждый сохранённый `cad_xrefs` edge виден под исходным DWG;
- resolved edge показывает target delivery path;
- missing edge показывает original path и отсутствие кандидатов;
- одинаковая missing dependency отмечается как используемая несколькими DWG;
- обновление страницы воспроизводит дерево из PostGIS.
