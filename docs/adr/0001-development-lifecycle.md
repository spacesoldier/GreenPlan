# ADR-0001: Разработка ведётся через ADR, phase plan и тестовые контракты

- Status: Accepted
- Date: 2026-09-25
- Owners: architecture and development team
- Related phase: all phases
- Supersedes: —
- Superseded by: —

## Context

Проект объединяет CAD-конвертацию, пространственную модель, нормативные правила, web-интерфейс и потенциально safety-critical рекомендации. Если сначала писать функции, а архитектурные причины и критерии корректности восстанавливать позже, разные подсистемы быстро получат несовместимые понятия версии, статуса и источника истины.

## Decision

Каждая новая фаза после ретроспективной Phase 1 выполняется в порядке:

```text
Accepted ADR(s)
  -> phase plan with acceptance criteria
  -> failing contract/acceptance tests
  -> smallest implementation that passes them
  -> regression/integration verification
  -> phase report with evidence
```

Изменение внутри принятой архитектуры может не требовать нового ADR, но обязано иметь тест и быть указано в phase plan. Изменение границы компонента, источника истины, модели консистентности, безопасности, лицензирования или технологического стека требует ADR.

## Alternatives considered

### Планировать только задачами backlog

Недостаточно: backlog показывает последовательность работ, но не сохраняет причины системных решений.

### Документировать после реализации

Подходит для отчёта, но создаёт риск рационализации уже написанного кода и не даёт тестам предварительного контракта.

## Consequences

### Positive

- изменения имеют проверяемую цель и границы;
- тесты отражают продуктовый контракт до реализации;
- архитектурные компромиссы остаются видимыми;
- фазу можно остановить по объективному gate.

### Negative / trade-offs

- небольшая предварительная стоимость документации;
- ADR и планы необходимо поддерживать при изменении решения;
- прототипирование, способное изменить архитектуру, оформляется как time-boxed spike.

## Verification

- каждый Phase 2+ plan содержит ссылки на принятые ADR;
- в PR/наборе изменений тесты появляются до production-функции либо в том же атомарном изменении с явно различимым контрактом;
- завершённая фаза имеет отчёт с командами проверки и известными ограничениями;
- отсутствие принятого ADR блокирует работу, меняющую архитектурные границы.
