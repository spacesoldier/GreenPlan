# ADR-0046: Импорт библиотеки растений из CAD-блоков

- Status: Accepted
- Date: 2026-09-29
- Owners: CAD ingestion / biology domain
- Related phase: Phase 4, iteration 2
- Supersedes: —
- Superseded by: —

## Context

Файл `dataset/Шаблоны значков.dwg` содержит графические обозначения растений и русские названия, пригодные для начального наполнения plant library. Диагностика показала, что предположение «один слой — одно растение» недостаточно:

- DWG имеет формат AC1032 и весит 2 426 777 байт;
- зарегистрировано 96 слоёв;
- в Model находятся 117 сущностей: 105 `INSERT`, 10 `LWPOLYLINE`, одна таблица и один `MTEXT`;
- 105 вставок используют 99 уникальных имён блоков, всего найдено 136 непечатных определений блоков;
- листы `Лист1` и `Лист2` пусты;
- часть названий пород находится в блоках, часть — в семантических слоях, а часть имён является служебной, сокращённой или ошибочной.

Символы могут содержать тысячи примитивов, включая HATCH, LINE и ARC. Простое flatten-преобразование или сохранение только превью уничтожит редактируемую CAD-семантику.

## Decision

`Шаблоны значков.dwg` импортируется как версионируемая CAD-библиотека, а не как проект улицы. Источник идентифицируется SHA-256 и версией importer. Для каждого определения блока создаётся кандидат символа с исходным именем, handle, extents, base point, единицами, вложенными ссылками, слоями и атрибутами.

Определение растения использует совокупность сигналов в порядке объяснимого приоритета:

1. нормализованное имя определения блока и имя `INSERT`;
2. атрибуты блока, включая обозначение породы, номер и существующий код;
3. семантические имена слоя;
4. текст и таблицы рядом с экземпляром;
5. контекст вложенных блоков и повторяемость экземпляров.

Нормализация учитывает регистр, `ё/е`, пробелы, единственное/множественное число и словарь проверенных опечаток, но не удаляет исходное имя. Служебные имена (`A$C…`, `*T…`, коды без надёжного соответствия) не создают автоматически утверждённый таксон.

Модель данных расширяется сущностями:

- `biology.cad_symbol_libraries` — источник, edition/hash, importer version, units, status;
- `biology.plant_symbols` — исходная block identity, локальная геометрия, anchor/extents, preview artifact и review status;
- `biology.plant_symbol_profile_links` — кандидат или подтверждённая связь символа с `plant_profile`/`taxon`, confidence, метод и reviewer;
- при необходимости `biology.plant_name_aliases` — проверенные варианты и опечатки с provenance.

Первичный ключ происхождения символа строится из hash исходного asset и стабильной block identity, а не из имени слоя. Несколько графических вариантов одной породы сохраняются как отдельные symbols и связываются с одним plant profile. Совпадающие названия не приводят к разрушительному объединению геометрии.

Каноническая геометрия блока сохраняется в локальной системе координат. Для UI асинхронно строится ограниченное SVG/PNG preview. Исходная структура DXF/DWG, base point и преобразования сохраняются для последующего экспорта предложения обратно в DXF с `INSERT`, а не россыпью примитивов.

Импорт создаёт draft-карточки. Автоматически approved может стать только однозначная связь с уже подтверждённым plant profile по проверенному alias; новый таксон или профиль требует review.

## Alternatives considered

### Считать каждый слой отдельным растением

Отклонено по фактической структуре файла: многие слои служебные или стилевые, а имена пород находятся в block definitions.

### Превратить все блоки в плоские полилинии

Отклонено: теряются block identity, точка вставки, вложенность и возможность компактного DXF-экспорта.

### Сохранить только PNG-превью

Отклонено: картинка полезна в каталоге, но непригодна для создания CAD-результата.

## Consequences

### Positive

- библиотека получает реальные обозначения архитектора и сохраняет их CAD-качество;
- одна порода может иметь несколько вариантов символа;
- происхождение, авто-нормализация и ручное решение остаются проверяемыми;
- тот же символ можно использовать в preview, генерации и DXF export.

### Negative / trade-offs

- требуется отдельный importer block definitions и renderer preview;
- сложная геометрия потребует лимитов и фоновой обработки;
- грязные имена и опечатки всё равно создадут review queue.

## Verification

- integration audit исходного файла видит 96 слоёв, 105 INSERT и 99 уникальных имён вставленных блоков;
- повторный импорт того же SHA не создаёт дублей;
- символ сохраняет base point, extents, состав примитивов и nested block references;
- превью строится с ограничением ресурсов, не изменяя каноническую геометрию;
- служебные имена не создают approved taxon;
- подтверждённый символ можно экспортировать в тестовый DXF как block definition + INSERT и прочитать обратно.
