# ADR-0029 — Контекстное разрешение XREF и file-scoped очередь проблем

- Status: Accepted
- Date: 2026-09-28
- Owners: CAD ingestion, API, frontend

## Context

В поставке часто существуют одинаково названные DWG в исходных данных, проектном решении и
архивах. Выбор каждого совпадения вручную создаёт лишнюю работу, хотя структура каталогов часто
содержит достаточное доказательство. Одновременно служебные файлы размером в несколько килобайт
загромождают delivery tree и поиск кандидатов. После ручного решения UI также не объясняет,
продолжилась ли остановленная проверка файла.

## Decision

### Noise boundary

Файл размером не более 10 КиБ сохраняется в provenance, но получает роль `service_noise`, не
показывается в рабочем delivery tree и не участвует в CAD-анализе или XREF matching. Оригинальные
байты не удаляются. Порог является prototype policy и позднее должен стать настройкой workspace.

### Contextual XREF resolution

После exact relative-path lookup resolver рассматривает совпадения basename. Если ровно один
кандидат находится в подпапке каталога host drawing и остаётся единственным кандидатом после такого сужения,
он выбирается автоматически с методом `host_descendant`. Остальные глобальные совпадения при этом
отбрасываются. Если внутри подпапок остаётся несколько кандидатов, ссылка остаётся `ambiguous` и требует ручного выбора.

Архивная policy ADR-0028 сохраняется: host из архива не может выбрать target вне архива.
Автоматически разрешённая ссылка не создаёт finding. Решение и метод сохраняются в XREF evidence.

### File-scoped review queue

Активные findings группируются по `source_asset_id`. Заголовок группы показывает имя host-файла,
его непосредственный каталог и количество проблем. Закрытые (`resolved` или `accepted`) findings
исчезают из очереди, но остаются в БД и audit history.

После ручного разрешения XREF или waiver API считает оставшиеся open findings файла. Когда их нет,
создаётся новая попытка `xref_resolution` только для этого source asset. Она проверяет persisted
graph edges, пересчитывает workflow verdict и фиксирует audit event. Конвертер не запускается снова,
поскольку байты DWG не изменились.

UI показывает состояние проверки в кнопке и dock header. Закрываемая карточка сжимается и уходит
вправо; после последней проблемы аналогично исчезает группа файла. Это подтверждает действие, но
не подменяет persisted status анимацией.

### Host path presentation

В карточке XREF корневая папка поставки скрывается. Метка `Для чертежа` становится крупнее,
непосредственный каталог host drawing выделяется жирным, а имя DWG получает отдельную подсветку.

## Consequences

- ручной review остаётся только для настоящей неоднозначности;
- мелкий мусор не влияет на граф, сохраняя provenance;
- повторная проверка имеет file-level attempt и наблюдаемый результат;
