# ADR-0040 — Независимая готовность геометрии и семантики при публикации

- Status: Proposed
- Date: 2026-09-29
- Owners: backend, CAD ingestion, frontend, landscape architecture
- Related phase: Phase 3, iteration 6
- Supersedes: частично уточняет ADR-0017 и ADR-0020
- Superseded by: —

## Context

Полный комплект подрядчика может содержать сотни и тысячи CAD-слоёв. Ручная классификация каждого
слоя до первого просмотра модели не укладывается в рабочий процесс архитектора. При этом уже после
разрешения XREF, выбора набора корневых чертежей и проверки конвертации геометрия полезна: её можно осматривать,
сравнивать с исходником и использовать для дальнейшей настройки viewer.

Текущий прототип технически не включает полноту классификации в publication gate. Инженерское
принятие сейчас требует выбранный master, но целевой контракт требует publication root set, отсутствие открытых critical findings и допустимый fidelity
verdict. `publish_revision` требует состояние `ready_to_publish`, после чего создаёт canonical model
со значениями `assembly_status=needs_review` и `semantic_coverage=0`.

Такое поведение позволяет продолжить работу, но одно слово «опубликован» смешивает разные утверждения:

- геометрия собрана достаточно полно для просмотра;
- происхождение объектов прослеживается;
- слои семантически разобраны;
- модель пригодна для нормативной проверки;
- модель пригодна для автоматической расстановки растений.

Эти утверждения не равнозначны. Кроме того, публикационный импорт сейчас повторно применяет
детерминированный классификатор имён слоёв. Подтверждённые человеком или ассистентом intake-решения
должны проецироваться в canonical model явно, иначе inspector и viewer могут показывать разные классы.

## Decision

### 1. Разделить readiness на независимые измерения

Ревизия и canonical model получают явный readiness snapshot:

- `geometry_readiness` — выбран хотя бы один допустимый publication root, производное DXF читается, геометрия импортируема;
- `dependency_readiness` — XREF разрешены либо имеют документированный waiver;
- `fidelity_readiness` — critical findings отсутствуют, остальные приняты или остаются видимыми;
- `semantic_readiness` — измеримое покрытие слоёв и объектов подтверждёнными классами;
- `constraint_readiness` — все классы, обязательные для выбранной нормативной задачи, подтверждены;
- `render_readiness` — сцена имеет extent, spatial focus и поддерживаемые render primitives.

Каждое измерение содержит статус `ready | needs_review | blocked`, числовые метрики, причины и
fingerprint входов. Общий workflow state не заменяет эти измерения.

### 2. Разрешить preview publication без классификации всех слоёв

Проверка и публикация геометрического preview не требуют стопроцентной `semantic_readiness`, если:

1. выбран непустой набор верхнеуровневых publication roots;
2. закончены conversion/inventory jobs;
3. нет открытых critical fidelity findings;
4. XREF разрешены или явно приняты waiver-решением;
5. для каждого выбранного root существует читаемое производное представление;
6. пользователь видит количество и долю неразобранных слоёв до подтверждения публикации.

Такая публикация маркируется как `preview` и `needs_review`. Неопределённые слои не отбрасываются:
они публикуются с исходным именем, source asset, CAD handle и классом `unknown`/`unknown.constraint`.

Пока отдельный API-режим не реализован, существующая публикация прототипа трактуется именно как
preview canonical model, а не как утверждённый дендроплан или нормативно готовый результат.

### 3. Ввести task-specific gate вместо требования разобрать всё

Автоматическая расстановка растений и нормативная проверка получают отдельный gate. Для выбранной
области работ должны быть разобраны как минимум потенциально значимые классы:

- здания и сооружения;
- проезжая часть, тротуары, дорожки и борты;
- инженерные сети и их охранные зоны;
- границы работ и нормативные зоны;
- рельефные ограничения;
- существующая и проектируемая растительность;
- озеленяемые поверхности и другие выбранные planning surfaces.

Unknown-слой, геометрия которого пересекает область расчёта и может быть ограничением, переводит
`constraint_readiness` в `blocked` или `needs_review`. Служебный текст вне области работ не должен
блокировать задачу только ради формального достижения 100%.

### 4. Считать semantic coverage явно

Минимально публикуются две метрики:

```text
layer_coverage = confirmed_relevant_layers / relevant_layers
object_coverage = objects_on_confirmed_relevant_layers / relevant_objects
```

`not_applicable` считается разобранным только после подтверждённого rule/assistant/human решения.
Пустые слои не увеличивают покрытие. Метрики считаются по неизменяемому classification snapshot,
привязанному к revision.

### 5. Проецировать intake-классификацию в canonical model

Публикация создаёт immutable `classification_snapshot` для revision. При импорте объекта применяется
приоритет:

1. подтверждённое human correction;
2. подтверждённое human acceptance;
3. принятое assistant assignment с provenance;
4. deterministic rule результата текущей версии taxonomy;
5. `unknown`.

Ключ сопоставления включает source asset identity и исходное имя/identity CAD-слоя. Совпадение только
по нормализованному имени между разными файлами недостаточно. У каждого объекта сохраняются
`classification_source`, `classification_version` и ссылка на review/evidence.

### 6. Сделать долг видимым в UI

Экран проверки и публикации показывает:

- геометрическую и семантическую готовность отдельно;
- число подтверждённых, неизвестных и неприменимых слоёв;
- предупреждение «публикуется preview-модель»;
- список причин, блокирующих не просмотр, а конкретно planning/constraint run;
- ссылку назад на фильтр неразобранных слоёв.

## Alternatives considered

### Блокировать публикацию, пока не классифицирован каждый слой

Отклонено: стоимость работы не зависит от полезности слоя, а служебная графика и подписи могут
составлять большую часть поставки. Это блокирует проверку геометрии без повышения её достоверности.

### Публиковать и считать модель полностью готовой

Отклонено: создаёт ложное ощущение нормативной и предметной готовности, позволяет unknown-геометрии
неявно исчезнуть из расчёта ограничений.

### Отбрасывать все unknown-слои

Отклонено: неизвестный слой может оказаться сетью, зданием, охранной зоной или озеленяемой площадью.
Он должен оставаться видимым и доступным для последующего разбора.

## Consequences

### Positive

- пользователь может перейти к viewer без ручного разбора всего комплекта;
- semantic debt измерим и не скрыт;
- публикация не теряет unknown-геометрию;
- planning gate проверяет необходимые данные, а не формальный процент;
- подтверждённые intake-классы не расходятся с canonical model.

### Negative / trade-offs

- слово «публикация» требует явного режима и пояснения;
- readiness snapshot и classification projection усложняют publish transaction;
- необходимо определить relevant-layer policy для каждой вычислительной задачи;
- старые модели потребуют пересчёта coverage или будут помечены `unknown`.

## Verification

- revision с неразобранными слоями и без critical fidelity findings может создать preview model;
- preview сохраняет и рисует объекты unknown-слоёв;
- UI показывает одинаковые layer/object coverage с API;
- подтверждённый вручную класс попадает в canonical object без повторной догадки по имени;
- одинаковые названия слоёв из разных source assets не сливаются в одно решение;
- constraint run отклоняется при неизвестном потенциальном ограничении в ROI;
- служебный `not_applicable` вне ROI не блокирует просмотр;
- readiness fingerprint меняется при новой классификации или новом составе XREF.
