# Нормативный реестр и объяснимость

## Принцип

Нормативный документ — источник, а не исполняемый код. Исполняемым становится только проверенное правило с владельцем, версией, точной цитатой и областью применимости. Это защищает от двух ошибок: LLM-галлюцинации пункта и применения корректного расстояния к неверному виду объекта.

Указанные в задании ориентиры включают СП 42.13330.2016, ПП Москвы № 743-ПП, ПП Москвы № 623-ПП и требования МГСН. Локальный файл `Нормативные акты ссылки.docx` дополнительно перечисляет, среди прочих, СП 82.13330.2016, ТСН 30-307-2002, ГОСТ 21.508-2020 и акты о благоустройстве. До внесения конкретного числового правила команда обязана открыть действующую редакцию первоисточника и проверить пункт/таблицу у профильного эксперта.

## Карточка правила

```yaml
rule_id: utility.water.tree.clearance.v1
status: approved
source:
  document_id: moscow-743-pp
  edition_checked_at: 2026-09-21
  locator: "пункт/таблица заполняется после юридической проверки"
  canonical_url: "..."
applies_when:
  planting_kind: tree
  obstacle_class: utility.water
effect:
  type: minimum_distance
  distance_m: null
  comparison: ">="
evidence_owner: "роль/эксперт"
```

Пока `distance_m` или `locator` не заполнены и не утверждены, правило не может выпускать автоматическую разрешающую рекомендацию. Оно может только блокировать зону в режиме safety-first либо запросить ревью.

## Отчёт по посадке

```json
{
  "planting_id": "TREE-00042",
  "status": "proposed",
  "profile_id": "tree.standard",
  "coordinate_m": [123.45, 678.9],
  "decision": "allowed",
  "checks": [
    {"rule_id": "utility.water.tree.clearance.v1", "result": "pass", "actual_m": 3.2, "required_m": 2.0},
    {"rule_id": "existing_tree.tree.clearance.v1", "result": "pass", "actual_m": 5.6, "required_m": 5.0}
  ],
  "input_provenance": ["cad:source-7:entity-4A2"],
  "rulebook_version": "2026-09-21",
  "run_id": "..."
}
```

Числа в примере иллюстративны. В продакшн-отчёте у каждой проверки указываются `document_id`, `locator`, URL/архив первоисточника и версия правила.

## Роль LLM в контуре НПА

LLM может индексировать загруженную книгу/НПА, извлечь кандидаты `условие → действие → расстояние → ссылка`, подсветить конфликтующие формулировки и ответить на вопрос с цитатой. Результат маркируется `draft`; апрув выполняет уполномоченный специалист. Запрещено подставлять свободный ответ модели прямо в `approved` rulebook или в обязательное объяснение посадки.

Полный конвейер получения редакций, OCR, правовой сегментации, FTS-поиска, детерминированной проверки и экспертного принятия описан в [корпусе нормативов](15-regulatory-corpus-and-rule-ingestion.md). Наличие документа в локальной подборке не означает ни его действительность, ни автоматическую применимость.
