# Ревизия `Шаблоны значков.dwg`

- Дата: 2026-09-29
- Файл: `dataset/Шаблоны значков.dwg`
- Размер: 2 426 777 байт
- DWG signature: `AC1032`
- SHA-256: `99c54a33711c9d321967eb0c1e0c8e25ef137ca9d922ec112af4c067b55cef70`
- Диагностический DXF: `dataset/dxf/Шаблоны значков.dxf`, 11 863 057 байт, `AC1032`

## Вывод

Файл пригоден как исходная CAD-библиотека обозначений растений, но его нельзя импортировать по правилу «название слоя = растение». Более устойчивой единицей является block definition вместе с его именем, экземплярами INSERT, атрибутами и слоями составляющих примитивов.

## Наблюдаемая структура

| Показатель | Значение |
|---|---:|
| Зарегистрированные слои | 96 |
| Сущности в Model | 117 |
| INSERT в Model | 105 |
| Уникальные имена вставленных блоков | 99 |
| LWPOLYLINE | 10 |
| ACAD_TABLE | 1 |
| MTEXT | 1 |
| Непечатные/model block definitions | 136 |
| Layouts | Model, Лист1, Лист2 |

`Лист1` и `Лист2` не содержат полезных сущностей. Каталог находится в Model.

Из 99 используемых верхнеуровневых блоков 69 содержат HATCH. В них найдено 472 сплошных `SOLID`-заливки и небольшое число паттернов `ANGLE`, `ANSI31`, `TRIANG`, `ANSI37`, `ANSI36`, `HEX`, `AR-SAND`. Четыре блока имеют вложенные INSERT: `Ракитник русский → _ArchTick`, `Бузина → T11`, `Спирея серая или пепельная → BRANCHD`, `Акация (Робиния) → BRANCHT`. Это именно композиционные зависимости графики, а не связи между видами растений.

Среди читаемых имён блоков обнаружены, например: `Клен Гиннала`, `Дерен столонный`, `Бересклет`, `Сирень`, `Чубушник`, `Снежнеягодник`, `Тсуга`, `Можевельник горизонтальный`, `Яблоня декоративная`, `Клен красный`, `Роза`, `Спирея Аргута`, `Ива Маяк`, `Жимолость`, `Ракитник русский`, `Бузина`, `Сосна`.

Есть опечатки, сокращения и служебные имена: `акен`, `Вегейла`/`Вейела`, `д3`, `сб9`, `A$C…`, `*T…`, `LAND1-G4`. Их нельзя без проверки превращать в утверждённые биологические профили.

Некоторые слои действительно семантичны, например группы вида `ЗЕЛЕНЬ$ДЕРЕВЬЯ$…`, но внутри block definitions также используются общие слои графического стиля. Отдельные символы очень сложны: встречаются определения с тысячами HATCH/LINE/ARC. Следовательно, preview должен строиться отдельно, а исходная геометрия блока — сохраняться.

## Рекомендуемый импорт

1. Зарегистрировать исходный DWG и полученный диагностический DXF по hash.
2. Извлечь block definitions, base point, extents, units и nested references.
3. Связать все INSERT и атрибуты с определениями блоков.
4. Собрать кандидаты названий из block name, attributes, layers и соседнего текста.
5. Нормализовать только для поиска; исходные строки оставить неизменными.
6. Сопоставить с существующими taxa/plant profiles; неоднозначные случаи отправить на review.
7. Построить SVG/PNG thumbnails с лимитом сложности.
8. Проверить round-trip: выбранный symbol экспортируется как block + INSERT и снова читается.

Архитектурное решение: [ADR-0046](../adr/0046-cad-plant-symbol-library-ingestion.md).
