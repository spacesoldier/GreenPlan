# Сводный план

## Цель

Построить сервис, который принимает инженерную подоснову и контекст участка, находит геометрически допустимые места для озеленения и создаёт новый DXF. Исходный чертёж не переписывается: все предложения и служебные зоны находятся на выделенных слоях. Для каждой точки имеется машиночитаемое обоснование с проверяемой ссылкой на нормативный источник и конкретное правило.

Конкурсное ТЗ ставит в приоритет воспроизводимый конвейер `DXF → расчёт → DXF`, соблюдение отступов и интерпретируемость. UI и фотореалистичная визуализация не заменяют ядро.

## Результат MVP

| Результат | Обязательный контракт |
|---|---|
| Вход | Один DWG/DXF и связанные XREF; при необходимости — дополнительные PDF/SHP/GeoJSON |
| Выход CAD | Копия/производный DXF с исходными слоями без изменений и слоями `GREEN_AI_*` |
| Посадки | Как минимум деревья; далее кустарники и покрытия |
| Объяснения | `planting_explanations.json`, одно обоснование на каждую предложенную или отклонённую точку |
| Воспроизводимость | Манифест входов, версии конвертера/правил/конфига, deterministic seed |
| Запуск | CLI в Docker под Linux / МосТех.ОС; HTTP API — только вместе с OpenAPI |

## Границы первой версии

В первой версии не заявляются: автоматическое юридическое толкование НПА, бесконтрольное совмещение листов PDF, правка исходных CAD-слоёв, точное определение типа коммуникации по одной графике без подтверждения, полноценный CAD-редактор и генерация фото как источник проектного решения.

Неопределённые слой, масштаб, система координат, трансформация XREF или расстояние правила переводят участок/объект в состояние `needs_review`; движок не маскирует эту неопределённость посадкой.

## Этапы

Исполнение этапов управляется документами [dev-plan](dev-plan/README.md) и [ADR](adr/README.md). Нумерация ниже описывает предметное развитие исходного конкурсного MVP; формальные engineering phases и их фактический статус находятся в `docs/dev-plan/`.

### 0. База проекта

- утвердить словарь канонических классов и формат реестра правил;
- зарегистрировать официальные редакции обязательных НПА, извлечь адресуемые фрагменты и провести экспертный review первых кандидатов правил;
- реализовать кликабельный OSM-слой с очередью кандидатов зданий, не изменяющей approved model напрямую;
- выбрать Docker-образ конвертации DWG→DXF, пригодный для Linux;
- задать структуру артефактов запуска и политику хранения исходников;
- подготовить один ручной слой-маппинг для каждого пилота.

**Выход:** пустой, но запускаемый конвейер и тестовые фикстуры.

### 1. Пилот Песчаного переулка

- развернуть основной DWG и XREF, зафиксировать дерево зависимостей;
- конвертировать в канонический DXF, проинвентаризировать слои/блоки/единицы;
- собрать границу работ и минимум ограничений;
- сгенерировать деревья и выгрузить DXF + JSON-объяснения;
- сравнить с дендропланом и ведомостью как с референсом, а не как с безусловной истиной.

### 2. Пилот Куликовской улицы

- повторить импорт на независимой структуре данных;
- использовать отдельные файлы генплана, посадок, благоустройства и ведомости как проверку слияния дисциплин;
- расширить словарь слоёв и правила классификации только после фиксации расхождений.

### 3. Регрессия на остальных 18 объектах

- для каждого объекта сформировать паспорт входных данных и статус готовности;
- запускать импорт и проверки пакетно;
- новую эвристику принимать лишь вместе с тестом, который воспроизводит обнаруженную проблему;
- различать `passed`, `passed_with_review`, `blocked_by_input`, чтобы не выдавать отсутствие данных за ошибку генератора.

### 4. Упаковка и демонстрация

- Dockerfile/compose, инструкция, тестовый набор и хеши входов;
- сценарий демонстрации: вход → карта ограничений → посадки → DXF в CAD → JSON-обоснование;
- после стабильного ядра — 3D-просмотр и фотовизуализации.

## Критерии готовности к следующему этапу

- **после импорта:** единицы и преобразования известны; XREF либо разрешены, либо явно отмечены; у каждой геометрии есть происхождение;
- **после генерации:** ни одна принятая посадка не пересекает запретную зону, соблюдены межпосадочные расстояния, есть ссылка на правило;
- **после экспорта:** исходные CAD-сущности/слои не изменены, `GREEN_AI_*` можно выключить независимо;
- **перед масштабированием:** оба пилота повторяемо дают один и тот же результат при одинаковых входах, конфиге и версии реестра.
