# DWG→DXF: сохранность и gate конверсии

## Короткий ответ

Преобразование **возможно и достаточно надёжно для нашего 2D-профиля**, но не бывает безусловно «без потерь» для любого DWG. DWG — нативная база данных чертежа, DXF — её обменное представление. DXF умеет хранить графические entities, блоки, таблицы слоёв/стилей, objects, layouts, handles, XDATA и ссылки; значит, стандартная геометрия генплана не должна растрироваться или упрощаться при конверсии в тот же уровень DXF.

Термин «без потерь» в проекте означает: **визуальная, геометрическая и семантическая сохранность объектов объявленного профиля**, доказанная автоматическими проверками. Он не означает равенство байтов, сохранение всех служебных данных неизвестного плагина или обратимость DXF→DWG без изменения handles/внутреннего порядка.

Операционный контракт новой пользовательской загрузки, direct-read fallback, XREF completeness и запрет публикации без сравнения зафиксированы в [ADR-0018](adr/0018-evidence-gated-cad-reading-and-conversion.md) и [Phase 3](dev-plan/phase-03-controlled-project-intake.md).

## Объявленный профиль GreenPlan v1

| Класс | Политика |
|---|---|
| 2D/3D `LINE`, `ARC`, `CIRCLE`, `ELLIPSE`, `POINT`, `LWPOLYLINE`, `POLYLINE`, `SPLINE`, `HATCH` | поддержать и проверить геометрию/свойства |
| `TEXT`, `MTEXT`, размеры, выноски | сохранить; проверять текст, стиль и bounding box, учитывая шрифты |
| layers, linetypes, colours, lineweights, blocks, inserts, attributes | сохранить и сравнить инвентарь |
| layouts, viewport, plot style | best effort; сохранить, но не считать частью геометрической готовности планировщика |
| XREF | разрешить в канонической сцене и зафиксировать трансформации; сохранять оригинальные ссылки в производном DXF только если они переносимы |
| изображения/PDF/DGN underlays | сохранить ссылку и путь при возможности; наличие файла проверять отдельно |
| proxy/custom/AEC/Civil 3D объекты | не считать распознанными: сохранить как proxy, explode/экспортировать в геометрию только по утверждённой политике, иначе `needs_review` |
| цифровые подписи, VBA, неизвестные extension dictionaries/reactors | не обещать сохранность; выявлять и протоколировать |

Пилотные главные файлы Песчаного переулка и Куликовской улицы имеют сигнатуру `AC1032` (AutoCAD 2018). Для них целевой формат первого контура — **ASCII DXF 2018/AC1032**, без down-save до R12/R2000. Снижение версии является отдельным преобразованием с отдельной потерей возможностей и запрещено в стандартном запуске.

## Рекомендуемый конвейер

```text
оригинальный DWG (не меняется)
  → inventory pre: версии, entities, objects, classes, layers, blocks, XREF, proxy
  → DWG→DXF AC1032 через закреплённый CAD-адаптер
  → audit/repair только с отдельным статусом и исходным логом
  → inventory post + сравнение
  → геометрическое/визуальное сравнение
  → производный DXF с GREEN_AI_*
```

Первый кандидат на адаптер — ODA File Converter в контролируемой Linux-установке: он поддерживает CLI, выбор входного фильтра, целевого типа/версии, рекурсивную обработку и audit. По FAQ ODA не-член может использовать File Converter для некоммерческих применений; это подходит как рабочая гипотеза для хакатона, но не является юридическим заключением для дальнейшего внедрения. Перед включением бинарника в Docker-образ или его распространением надо отдельно принять актуальную EULA/проверить разрешение на redistribution. Архитектура не должна зависеть от установки на машине разработчика.

Для переносимого запуска подготовлен [`../docker/README.md`](../docker/README.md): open-source Docker-адаптер содержит только системные зависимости и `xvfb`, а пользователь монтирует полученный им ODA runtime read-only. Реальный `AC1032` DWG успешно прошёл через этот адаптер в DXF `AC1032` (57 612 163 байта, exit code 0). Так мы не распространяем ODA в образе. LibreDWG 0.13.3 собран отдельно как GPL-диагностический reader; его результат на том же файле и ограничения зафиксированы в [`../reports/libredwg-probe.md`](../reports/libredwg-probe.md).

Для инвентаризации до установки конвертера есть read-only скрипт [`../scripts/scan_dwg_inventory.sh`](../scripts/scan_dwg_inventory.sh). Он читает только шесть первых байтов каждого DWG, создаёт CSV/Markdown-статистику версий и **не** выдаёт вердикт «без потерь» по одному заголовку.

Первый запуск уже выполнен на `dataset`: из 1 009 файлов с расширением `.dwg` распознаны 819 CAD-файлов — 495 `AC1032`, 324 более ранних `AC1015…AC1027`; неизвестных `AC*`-версий нет. Остальные 190 не имеют DWG-сигнатуры (в основном служебные `PaxHeader`) и не должны подаваться в конвертер. Полный отчёт: [`../reports/dwg-inventory/report.md`](../reports/dwg-inventory/report.md).

Не использовать для главного контура «самописный парсер DWG» или LibreCAD/QCAD как гарантированный декодер R2018: они могут быть полезны для просмотра/ограниченных DXF, но не являются доказательством семантически полной конверсии R2018 DWG.

## Что реально может теряться или меняться

1. **Объекты вертикальных продуктов и плагинов.** Civil 3D, Map 3D, Plant 3D, custom ObjectARX/AEC classes могут быть записаны как proxy; без object enabler их параметры недоступны планировщику, даже если CAD их визуально показывает.
2. **Связи вне файла.** XREF, изображения, PDF-underlay, SHX/TTF-шрифты, plot config и внешние базы не станут самодостаточными от одной конверсии. Их пути, наличие и трансформации надо проверять как зависимости.
3. **Внутренняя идентичность.** Handles, владельцы, dictionaries, reactors, порядок объектов и audit-исправления могут измениться. Нельзя связывать наш отчёт только с исходным handle; нужен стабильный `feature_id` и source provenance.
4. **Текст и печать.** Отсутствующий шрифт меняет внешний вид/размер текста; CTB/PC3 и настройки принтера не гарантируют совпадение листа на другой машине.
5. **Координатная интерпретация.** DXF не доказывает, что плоские числа — это метры либо конкретная CRS. Кроме того, часть 2D-сущностей хранится в OCS, а не напрямую в WCS; наивное чтение пар `10/20` может дать неверную геометрию.
6. **Понижение версии DXF.** Старые варианты не способны выразить все более новые entities/objects, стили и данные приложения. Нельзя оптимизировать размер или совместимость down-save без отдельной матрицы потерь.

## Gate сохранности

Конверсия получает один из статусов: `accepted`, `accepted_with_review`, `rejected`.

### Обязательные проверки

| Проверка | Критерий `accepted` |
|---|---|
| Формат и версия | DXF AC1032; CAD открывает файл без critical error |
| Слои/блоки | имена и число объявленных layers/blocks совпадают либо разница объяснена производным служебным слоем |
| Геометрия профиля v1 | число entities по типам и extents совпадают; у сопоставленных объектов отклонение координат не выше установленной CAD tolerance |
| Стили | совпадают layer, colour, linetype, lineweight, visibility для объектов профиля |
| Текст | совпадают содержимое/стиль; отсутствующие шрифты перечислены отдельно |
| XREF | все критические ссылки найдены и имеют проверенную матрицу вставки; иначе `accepted_with_review`/`rejected` |
| Proxy/custom | их количество, class и handles инвентаризированы; критичные для ограничений proxy дают `rejected` |
| Визуальный diff | растровые PDF/PNG из model space/layout для выборочных листов не имеют необъяснимых различий |
| Семантика | объекты, используемые в расчёте, имеют подтверждённый `semantic_class` и происхождение |

Порог геометрической точности задаётся в конфиге и зависит от единиц/точности исходника; его нельзя молча подменять фиксированным миллиметром. До определения единиц статус — `needs_review`.

### Допуск для результата GreenPlan

Мы не обязаны доказать, что каждый неиспользуемый metadata-object идентичен DWG. Но обязаны доказать, что:

- геометрия и слои, от которых зависит расчёт посадок, сохранены;
- все нераспознанные/недостающие зависимости отражены в отчёте;
- исходные объекты производного DXF не были намеренно изменены нашим генератором;
- добавлены только `GREEN_AI_*` и разрешённые служебные записи;
- итоговый DXF открывается целевым CAD-просмотрщиком.

## Практическое решение для проекта

1. На старте преобразовать два пилотных `AC1032` DWG в DXF той же версии и сохранить оба формата.
2. Сделать `cad-inventory` до/после конверсии; он не должен полагаться на один только DXF-parser.
3. Разрешить XREF в отдельной канонической сцене, сохранив исходный граф ссылок и матрицы вставки.
4. Выпускать `plan.dxf` только при `accepted` либо с явным блокирующим предупреждением `accepted_with_review`.
5. Никогда не удалять исходный DWG ради уменьшения поставки; в демонстрации показывать пару `source.dwg` + `plan.dxf` + `validation.json`.
