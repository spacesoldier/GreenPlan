## Управление разработкой

- [Планы фаз](dev-plan/README.md) — статус, scope, тесты до реализации, acceptance gates и отчёты Phase 1–3.
- [Architecture Decision Records](adr/README.md) — принятые и предлагаемые архитектурные решения с альтернативами и проверками.

Для Phase 2 и далее порядок обязателен: принять ADR → утвердить план фазы → написать тесты контрактов → реализовать функции → сохранить отчёт проверки. Общие архитектурные документы выше описывают целевую систему, но не заменяют phase status и evidence.

## Главная архитектурная договорённость

LLM не принимает решение о допустимости посадки. Допустимость вычисляет детерминированный геометрический движок по опубликованной версии правил. LLM допускается только как ассистент импорта: предлагает семантику неизвестного слоя, извлекает кандидаты правил из документов и формулирует черновое человеческое объяснение. Все такие предложения проходят подтверждение специалистом и сохраняются с происхождением.

## Термины

- **каноническая модель участка** — нормализованный набор геометрий в метрах с исходным идентификатором сущности, назначенной семантикой и происхождением;
- **правило** — версионированная машиночитаемая карточка требования, а не свободный текст НПА;
- **посадка** — предложенный объект с координатой, видом/типом, статусом и полной трассой объяснения;
- **пилот** — объект, на котором проверяется не только генерация, но и устойчивость импорта и воспроизводимость результата.
