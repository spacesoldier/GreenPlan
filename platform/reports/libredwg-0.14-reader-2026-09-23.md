# LibreDWG 0.14: повторная reader-диагностика

Дата прогона: 2026-09-23.

## Сборка

- источник: официальный GNU release `libredwg-0.14.tar.gz`;
- локальная копия: `vendor/libredwg/packages/libredwg-0.14.tar.gz`;
- SHA-256: `cb6ee0b078c6d9e0f09d66f1feac33ba6342df88ae544e9f9335fab475218351`;
- фактическая версия внутри контейнера: `dwgread 0.14`;
- JSON создавался временно и удалялся после записи метрик и полного `stderr` в PostgreSQL.

## Результат на исходных 819 DWG

| Показатель | LibreDWG 0.13.3 | LibreDWG 0.14 |
|---|---:|---:|
| Проверено уникальных исходников | 819 | 819 |
| Успешно создан JSON | 792 | 819 |
| Ошибка reader | 27 | 0 |
| Исправлено прежних отказов | — | 27 |

Все 27 файлов, которые не читались версией 0.13.3, успешно прочитаны версией 0.14. Это существенное улучшение совместимости, но не доказательство полной семантической эквивалентности DWG: каждый файл всё ещё выдаёт диагностические сообщения.

Суммарный объём временно созданного JSON составил 42 012 645 498 байт. Постоянно его не храним: это почти 39,2 GiB. Сохранённый `stderr` занимает около 130 MiB. Число строк, отфильтрованных по `warning|error|fail|unsupported`, меняется от 8 до 83 673 на файл, поэтому сам факт `return code = 0` нельзя считать знаком «без потерь».

Самый шумный файл: `20. Макеева С. ул/.../ИП_Макеева С. ул.dwg`, 83 673 диагностические строки, временный JSON около 275 MiB.

## Интерпретация

Reader 0.14 теперь пригоден как второй независимый декодер для всего текущего набора. Канонический DXF по-прежнему создаёт ODA File Converter. Отдельный прогон `dwg2dxf` в R2018 нужен для проверки именно экспортёра LibreDWG; его результаты должны храниться отдельной стадией `libredwg_dxf` и не публиковаться вместо ODA без геометрического сравнения.
