# Полный прогон DWG → DXF

Дата завершения: 2026-09-23.

## Итог

- файлов с расширением `.dwg` в dataset: **1009**;
- настоящих DWG с известной сигнатурой `AC10xx`: **819**;
- служебных `PaxHeader`, не являющихся DWG: **190**, в очередь не подавались;
- уникальных исходных путей, обработанных ODA: **819**;
- опубликованных DXF: **819**;
- пропущенных, пустых или лишних DXF: **0**;
- DXF с версией, отличной от `AC1032`: **0**;
- отказов ODA: **0**;
- суммарный объём DWG: **2 560 259 527 байт** (2,38 GiB);
- суммарный объём DXF: **15 228 849 108 байт** (14,18 GiB);
- среднее увеличение объёма: **5,95 раза**.

В PostgreSQL присутствует 820 ODA-стадий: одна лишняя стадия относится к историческому повторному пилотному job для того же пути Песчаного переулка. Число уникальных исходных путей и публикаций остаётся 819.

Каждая публикация копировалась атомарно и проверялась SHA-256. После прогона отдельная файловая сверка построила ожидаемый путь для каждого DWG и проверила наличие, ненулевой размер и `$ACADVER = AC1032` у каждого результата.

## Размещение

Для файла внутри улицы результат сохраняет весь относительный путь после папки улицы:

```text
dataset/Пилотный проект 20 улиц/<N. улица>/<путь>/file.dwg
dataset/Пилотный проект 20 улиц/<N. улица>/dxf/<путь>/file.dxf
```

Единственный DWG вне проектов, `dataset/Шаблоны значков.dwg`, опубликован как `dataset/dxf/Шаблоны значков.dxf`.

## LibreDWG

LibreDWG является вторым диагностическим reader, а не источником DXF. JSON успешно получен для **792 уникальных DWG**; для **27** файлов LibreDWG 0.13.3 не создал JSON. ODA при этом успешно создал и опубликовал DXF для всех 27. Для отказов сохранено от 17 до 607 диагностических строк; полный список находится в [libredwg-failures-2026-09-23.md](libredwg-failures-2026-09-23.md).

Отказ LibreDWG означает ограничение второго reader, а не доказанную потерю данных в DXF. Эти 27 файлов следует включить в приоритетный визуальный diff и проверку сущностей/слоёв через `ezdxf`.

## Диск и временные данные
