# GreenPlan

GreenPlan — прототип системы для работы с массивами документации проектов
ландшафтного проектирования. Система принимает смешанную поставку из DWG, DXF,
таблиц и сопроводительных материалов, восстанавливает связи между файлами,
помогает разобрать CAD-слои и формирует проверяемую пространственную модель
территории.

Цель проекта — генерация обоснованных предложений по озеленению территорий с
помощью генеративных подходов. Модель может предлагать семантику неизвестных
слоёв, варианты растений и композиционные решения, но нормативная допустимость
посадки проверяется детерминированными пространственными правилами и остаётся
под контролем специалиста.

> Проект находится в стадии прототипа. Он предназначен для исследования данных,
> проверки архитектурных решений и совместной работы с архитектором, а не для
> выпуска проектной документации без инженерной проверки.

## Что уже умеет прототип

- создавать проекты и загружать одиночные файлы или структуру папки;
- конвертировать DWG в DXF через ODA File Converter;
- независимо диагностировать DWG с помощью LibreDWG;
- находить XREF, показывать граф зависимостей и разрешать неоднозначные ссылки;
- инвентаризировать листы, слои и геометрические сущности CAD;
- предлагать и вручную назначать семантические классы слоям;
- публиковать выбранные корневые чертежи вместе с их XREF-замыканием;
- хранить каноническую геометрию, происхождение данных и решения оператора в
  PostgreSQL/PostGIS;
- показывать крупные CAD-модели в браузерном 2D-просмотрщике.

## Целевой конвейер

```text
поставка проекта
  -> инвентаризация и XREF-граф
  -> чтение DWG или контролируемая конвертация в DXF
  -> проверка полноты и классификация слоёв
  -> каноническая модель PostGIS
  -> зелёные зоны + нормативные ограничения
  -> подбор растений и генерация посадочных мест
  -> инженерная проверка, объяснение и экспорт
```

Следующий виток разработки добавляет реконструкцию зелёных поверхностей,
пересечение их со зданиями, дорогами, инженерными сетями и охранными зонами,
а также генератор посадок. Кустарники предполагается размещать вдоль допустимых
контуров, деревья — внутри площадей с учётом кроны, корневого объёма, нормативных
отступов и условий конкретного места.

## Основные компоненты

- Next.js — интерфейс загрузки, CAD-разбора, проверки и публикации;
- FastAPI — предметный API и управление intake-процессом;
- PostgreSQL и PostGIS — операционные данные, геометрия и нормативная модель;
- Redis и Celery — фоновые конверсионные и семантические задачи;
- ODA File Converter и LibreDWG — основной и диагностический DWG-контуры;
- Laya, Qwen, Gemma и Ax — экспериментальные локальные ассистенты;
- `ezdxf` — чтение DXF, сборка XREF и импорт сущностей.

Подробное назначение и границы компонентов приведены в
[системном обзоре](docs/system/README.md).

## Быстрый старт

Полный запуск требует локально полученного ODA File Converter и архива исходников
LibreDWG. Необходимые файлы не распространяются в этом репозитории.

```bash
git clone https://github.com/spacesoldier/GreenPlan.git
cd GreenPlan/platform
cp .env.example .env
# заполнить ODA_RUNTIME_HOST_DIR и заменить локальные пароли
docker compose --env-file .env up -d --build
```

После запуска:

- web-интерфейс: `http://127.0.0.1:38101`;
- OpenAPI: `http://127.0.0.1:38100/docs`;
- PostGIS: `127.0.0.1:36483`;
- операционный PostgreSQL: `127.0.0.1:35483`.

Перед первым запуском обязательно выполните полную
[инструкцию по установке](docs/system/deployment-and-operator-guide.md).

## Данные и лицензии

Исходные датасеты, рабочие артефакты, базы данных, веса моделей, локальные
публикации и `.env` исключены из Git. Скрипты загрузки моделей фиксируют версии и
контрольные суммы, но условия использования каждой модели проверяются отдельно.
ODA runtime подключается локально и не включается в публичные Docker-образы.

Собственный код проекта распространяется по [Apache License 2.0](LICENSE).
Лицензия проекта не заменяет лицензии сторонних моделей, нормативных публикаций,
CAD-конвертеров и входных материалов.
